## Overview

The Customers module manages customer profiles and their financial ledger (running balance driven by sales, payments, and returns).

| Sub-module      | Base Path                             | Description                                              |
| --------------- | ------------------------------------- | -------------------------------------------------------- |
| Customers       | `/customers`                          | CRUD for customer profiles                               |
| Ledger          | `/customers/:customerId/ledger`       | Paginated transaction ledger with running balance        |
| Ledger Export   | `/customers/:customerId/ledger/export/csv` | CSV download of filtered ledger               |
| Stats           | `/customers/:customerId/stats`        | Aggregated sales statistics for a single customer        |
| Ledger Overview | `/customers/ledger-overview`          | All customers with their current balance (dashboard use) |

### Customer Balance

`Customer.balance` is a running float maintained automatically:

- **Increases** when a sale is confirmed (debit = `totalAmount`).
- **Decreases** when a payment is recorded (credit = `amount`).
- **Decreases** when a return is processed (credit = `returnTotal`).
- Must be **exactly 0** before a customer can be soft-deleted.

### Soft Delete

Customers are soft-deleted (field `deletedAt` set, `isActive = false`). Soft-deleted customers do not appear in any list or dropdown endpoint. The `DELETE` endpoint enforces a zero-balance check before proceeding.

## Enums & Constants

### `CustomerTransactionType`

```
SALE        — Debit entry: sale confirmed (increases balance)
PAYMENT     — Credit entry: payment recorded (decreases balance)
RETURN      — Credit entry: sale return processed (decreases balance)
ADJUSTMENT  — Debit or credit: payment amount corrected
OPENING_BALANCE — Manual opening entry (not used by current flows)
```

### Customer Number Format

Auto-generated by the backend:

- Format: `CUST-YYYYMMDD-XXXX` (daily-sequential, zero-padded to 4 digits)
- Example: `CUST-20260618-0001`, `CUST-20260618-0002`
- Sequence resets to `0001` each calendar day.

## Customers API

### 1. Create Customer

```
POST /customers
Permission: customers.create
```

Creates a customer profile with an auto-generated `customerNumber`. All pricing fields (balance) start at 0.

#### Request Body

```json
{
  "name": "Al-Noor Traders",
  "email": "contact@alnoor.com",
  "phone": "+923001234567",
  "address": "Shop 12, Main Market",
  "city": "Lahore",
  "postalCode": "54000",
  "notes": "Preferred customer — net-30 terms"
}
```

| Field        | Type     | Required | Validation                    |
| ------------ | -------- | -------- | ----------------------------- |
| `name`       | `string` | Yes      | Min 2, Max 100 characters     |
| `email`      | `string` | No       | Valid email; globally unique  |
| `phone`      | `string` | No       | Max 20 characters             |
| `address`    | `string` | No       | Max 200 characters            |
| `city`       | `string` | No       | Max 50 characters             |
| `postalCode` | `string` | No       | Max 20 characters             |
| `notes`      | `string` | No       | Max 500 characters            |

#### Response `201 Created`

```json
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "customerNumber": "CUST-20260618-0001",
  "name": "Al-Noor Traders",
  "email": "contact@alnoor.com",
  "phone": "+923001234567",
  "address": "Shop 12, Main Market",
  "city": "Lahore",
  "postalCode": "54000",
  "notes": "Preferred customer — net-30 terms",
  "isActive": true,
  "balance": 0,
  "createdById": "user-uuid",
  "updatedById": null,
  "deletedAt": null,
  "createdAt": "2026-06-18T10:00:00.000Z",
  "updatedAt": "2026-06-18T10:00:00.000Z"
}
```

#### Errors

```json
{ "statusCode": 409, "message": "A customer with this email or phone already exists", "error": "Conflict" }
{ "statusCode": 400, "message": ["name must be longer than or equal to 2 characters"], "error": "Bad Request" }
```

### 6. Get Customer Stats

```
GET /customers/:customerId/stats
Permission: customers.read
```

Returns aggregated sales statistics for a single customer. Only `COMPLETED` sales are included in the aggregations.

#### Path Parameter

| Param        | Type   | Notes       |
| ------------ | ------ | ----------- |
| `customerId` | `uuid` | Customer ID |

#### Response `200 OK`

```json
{
  "totalSales": 12,
  "totalAmount": 185000,
  "totalPaid": 170000,
  "outstandingBalance": 15000,
  "averageSaleValue": 15416.67,
  "lastSaleDate": "2026-06-15T09:30:00.000Z",
  "salesThisMonth": 3,
  "amountThisMonth": 42000
}
```

| Field                | Type            | Description                                                          |
| -------------------- | --------------- | -------------------------------------------------------------------- |
| `totalSales`         | `number`        | Count of all COMPLETED sales                                         |
| `totalAmount`        | `number`        | Sum of `totalAmount` across all COMPLETED sales                      |
| `totalPaid`          | `number`        | Sum of `amountPaid` across all COMPLETED sales                       |
| `outstandingBalance` | `number`        | `totalAmount - totalPaid`                                            |
| `averageSaleValue`   | `number`        | `totalAmount / totalSales`; `0` if no sales                          |
| `lastSaleDate`       | `DateTime\|null` | Most recent COMPLETED sale date; `null` if no sales                 |
| `salesThisMonth`     | `number`        | Count of COMPLETED sales created from the 1st of the current month  |
| `amountThisMonth`    | `number`        | Sum of COMPLETED sales `totalAmount` from the 1st of current month  |

### 8. Delete Customer

```
DELETE /customers/:customerId
Permission: customers.delete
```

**Soft-deletes** the customer — sets `deletedAt = now()` and `isActive = false`. The customer disappears from all lists and dropdowns but the data is retained for historical records.

**Business Rule**: The customer's `balance` must be exactly `0` before deletion is allowed. Settle all outstanding payments or returns first.

#### Path Parameter

| Param        | Type   | Notes             |
| ------------ | ------ | ----------------- |
| `customerId` | `uuid` | Customer ID       |

#### Response `200 OK`

```json
{
  "message": "Customer deleted successfully"
}
```

#### Errors

```json
{ "statusCode": 404, "message": "Customer not found", "error": "Not Found" }
{
  "statusCode": 400,
  "message": "Cannot delete customer with outstanding balance of 15000. Please settle all dues before deleting.",
  "error": "Bad Request"
}
```

## Customer Ledger API

### 1. Get Ledger

```
GET /customers/:customerId/ledger
Permission: customers.read
```

Returns the customer's complete ledger with a running balance per entry, plus an overall summary. Optionally filtered by date range.

#### Path Parameter

| Param        | Type   | Notes       |
| ------------ | ------ | ----------- |
| `customerId` | `uuid` | Customer ID |

#### Query Parameters

| Param       | Type              | Default | Notes                              |
| ----------- | ----------------- | ------- | ---------------------------------- |
| `startDate` | `ISO date string` | —       | `YYYY-MM-DD` — inclusive lower bound |
| `endDate`   | `ISO date string` | —       | `YYYY-MM-DD` — inclusive upper bound |

#### Response `200 OK`

```json
{
  "customer": {
    "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "customerNumber": "CUST-20260618-0001",
    "name": "Al-Noor Traders",
    "email": "contact@alnoor.com",
    "phone": "+923001234567",
    "address": "Shop 12, Main Market",
    "balance": 15000,
    "createdAt": "2026-06-18T10:00:00.000Z"
  },
  "summary": {
    "totalSales": 185000,
    "totalPayments": 170000,
    "totalReturns": 0,
    "currentBalance": 15000,
    "totalTransactions": 8
  },
  "ledger": [
    {
      "id": "txn-uuid-1",
      "date": "2026-06-18T09:00:00.000Z",
      "type": "SALE",
      "reference": "SALE-20260618-0001",
      "description": "Sale SALE-20260618-0001",
      "debit": 25000,
      "credit": 0,
      "balance": 25000
    },
    {
      "id": "txn-uuid-2",
      "date": "2026-06-18T11:00:00.000Z",
      "type": "PAYMENT",
      "reference": "SALE-20260618-0001",
      "description": "Payment for SALE-20260618-0001",
      "debit": 0,
      "credit": 10000,
      "balance": 15000
    }
  ]
}
```

| Ledger Field  | Type     | Description                                                             |
| ------------- | -------- | ----------------------------------------------------------------------- |
| `type`        | `string` | `SALE`, `PAYMENT`, `RETURN`, `ADJUSTMENT`, `OPENING_BALANCE`            |
| `debit`       | `number` | Amount that increased the customer's balance (what they owe us)         |
| `credit`      | `number` | Amount that decreased the customer's balance (what we owe them / paid)  |
| `balance`     | `number` | Running balance after this entry (positive = customer owes us)          |

> Entries are returned in chronological order (`date ASC`). The `balance` column is recalculated server-side on every request based on the filtered date range — if `startDate` is set, the opening balance for entries before that date is **not** included.

### 2. Export Ledger to CSV

```
GET /customers/:customerId/ledger/export/csv
Permission: customers.read
```

Streams a CSV file of the customer's ledger. Accepts the same date-range filters as the ledger endpoint.

#### Path Parameter

| Param        | Type   | Notes       |
| ------------ | ------ | ----------- |
| `customerId` | `uuid` | Customer ID |

#### Query Parameters

Same as [Get Ledger](#1-get-ledger): `startDate`, `endDate`.

#### Response `200 OK`

```
Content-Type: text/csv
Content-Disposition: attachment; filename=customer-{customerId}-ledger.csv
```

CSV columns:
```
"Date","Type","Reference","Description","Debit","Credit","Balance"
"2026-06-18","SALE","SALE-20260618-0001","Sale SALE-20260618-0001","25000.00","0.00","25000.00"
"2026-06-18","PAYMENT","SALE-20260618-0001","Payment for SALE-20260618-0001","0.00","10000.00","15000.00"
```

> On the frontend, trigger this as a file download — open in a new tab or use a blob response handler. Do **not** treat it as a JSON `fetch`.

## Frontend Implementation Notes

### Status / Balance Colors (suggested)

| Condition              | Meaning                   | Color        |
| ---------------------- | ------------------------- | ------------ |
| `balance === 0`        | Fully settled             | Green        |
| `balance > 0`          | Customer owes money       | Amber/Orange |
| `balance < 0`          | We owe the customer       | Blue         |
| `isActive === false`   | Soft-deleted customer     | Gray / muted |

### Ledger Entry Type Chips

| Type             | Color  |
| ---------------- | ------ |
| `SALE`           | Red    |
| `PAYMENT`        | Green  |
| `RETURN`         | Blue   |
| `ADJUSTMENT`     | Amber  |
| `OPENING_BALANCE`| Gray   |

### Typical Screen Flows

**Customer List Screen**
- `GET /customers` with `search`, `page`, `limit`, `sortBy`, `sortOrder`.
- Show `balance` badge on each row — highlight if `> 0`.
- "New Customer" → `POST /customers`.

**Customer Detail Screen**
- `GET /customers/:customerId` for profile + recent sales.
- `GET /customers/:customerId/stats` for KPI cards (total sales, outstanding balance, avg sale value, this-month metrics).
- "Edit" → `PATCH /customers/:customerId`.
- "Delete" → `DELETE /customers/:customerId` — show balance warning if `balance !== 0`.

**Customer Ledger Screen**
- `GET /customers/:customerId/ledger` with optional `startDate`/`endDate` date-range pickers.
- Show summary cards (`totalSales`, `totalPayments`, `totalReturns`, `currentBalance`) at the top.
- Render ledger table with running `balance` column — color debit/credit cells differently.
- "Export CSV" button → `GET /customers/:customerId/ledger/export/csv` as file download.

**Receivables Dashboard / Ledger Overview**
- `GET /customers/ledger-overview` with `search` for the customers-with-balance overview.
- Sort by `balance DESC` client-side to surface highest-debt customers first.

**Dropdown / Autocomplete (e.g., in Create Sale form)**
- `GET /customers/dropdown` — minimal payload, fast load, ordered by name.
- Display as `{name} — {customerNumber}` with phone as secondary line.

### Decimal/Number Handling

`balance`, `totalAmount`, and all ledger `debit`/`credit`/`balance` fields are returned as **JS numbers** (not strings). No `parseFloat()` needed, but be aware of floating-point precision when doing client-side arithmetic.
