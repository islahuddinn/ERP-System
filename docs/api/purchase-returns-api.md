## Overview

A Purchase Return records the return of raw materials back to a supplier. It is always created against an existing **Purchase Order** (and optionally a specific **GRN**), and each line item is tied to a specific **RawMaterialBatch** so stock can be tracked at the batch level.

### Return Lifecycle

```
DRAFT ──submit──► PENDING ──approve──► APPROVED ──complete──► COMPLETED
  │                  │
  │                  └──reject──► REJECTED  (releases reserved stock)
  │
  └──cancel──► CANCELLED  (releases reserved stock)
```

- **DRAFT**: Editable. Items are immediately reserved (stock decremented) even at this stage.
- **PENDING**: Submitted for approval. Can be approved, rejected, or cancelled.
- **APPROVED**: All approvers signed off. Ready to complete.
- **COMPLETED**: Finalized. `batch.returnedQuantity` incremented, consumption log created.
- **REJECTED**: Any approver rejected. All reserved stock restored.
- **CANCELLED**: Cancelled from DRAFT or PENDING. All reserved stock restored.

> **Important**: Creating or updating a return **immediately decrements** `batch.availableQuantity` and `RawMaterial.currentStock` — even while the return is still `DRAFT`. If the return is later `REJECTED` or `CANCELLED`, that decrement is reversed.

### Approval Workflow (Optional)

Pass `approverIds[]` at creation to activate the workflow:
- Each listed approver calls `PATCH /:returnId/status` with `{ status: "APPROVED" }` (or the dedicated `/approve` endpoint if available).
- The return auto-transitions to `APPROVED` once **all** approvers have approved.
- Any single `REJECTED` decision immediately transitions the return to `REJECTED` and releases stock.
- Without approvers, use `PATCH /:returnId/status` to manually move through the flow.

## Enums & Constants

### `ReturnStatus`

```
DRAFT      — Editable; batch quantities already reserved (stock decremented)
PENDING    — Submitted for review/approval
APPROVED   — Approved; ready to complete
REJECTED   — Rejected by an approver; all reserved stock released
COMPLETED  — Finalized; batch.returnedQuantity incremented, consumption log created
CANCELLED  — Cancelled from DRAFT or PENDING; all reserved stock released
```

### `ReturnApprovalStatus`

```
PENDING   — Awaiting this approver's decision
APPROVED  — This approver approved
REJECTED  — This approver rejected
```

### Return Number Format

Auto-generated by the backend:

- Format: `PR-XXXXXX` (globally sequential, zero-padded to 6 digits)
- Example: `PR-000001`, `PR-000002`

### Decimal Fields

`totalAmount`, item `unitPrice`, and item `totalPrice` are returned as **JS numbers** (serialized from Prisma `Decimal`). No `parseFloat()` needed.

## How Stock Is Affected

| Event                          | `batch.availableQuantity` | `RawMaterial.currentStock` | `batch.returnedQuantity` |
| ------------------------------ | ------------------------- | -------------------------- | ------------------------ |
| Create return (DRAFT)          | −qty (immediate)          | −qty (immediate)           | unchanged                |
| Update return (add item)       | −qty (immediate)          | −qty (immediate)           | unchanged                |
| Update return (remove item)    | +qty (released)           | +qty (released)            | unchanged                |
| Update return (change qty)     | release old, reserve new  | release old, reserve new   | unchanged                |
| Status → REJECTED              | +qty (all released)       | +qty (all released)        | unchanged                |
| Status → CANCELLED             | +qty (all released)       | +qty (all released)        | unchanged                |
| Status → COMPLETED             | unchanged (already done)  | unchanged (already done)   | +qty (logged)            |

`unitPrice` for each return item is **always** taken from the batch's stored `unitCost` — any client-supplied value is ignored.

## Purchase Returns API

### 1. Create Purchase Return

```
POST /purchase-returns
Permission: purchases.create
```

Creates a return in `DRAFT` status. Each item's `unitPrice` is sourced from its batch's `unitCost`. Stock is decremented immediately.

#### Request Body

```json
{
  "purchaseOrderId": "po-uuid",
  "grnId": "grn-uuid",
  "returnDate": "2026-06-18",
  "reason": "Defective material — entire batch rejected",
  "remarks": "Supplier notified; credit note expected",
  "items": [
    {
      "rawMaterialId": "rm-uuid",
      "batchId": "batch-uuid",
      "grnItemId": "grn-item-uuid",
      "purchaseItemId": "po-item-uuid",
      "quantity": 20,
      "reason": "Batch failed quality check"
    }
  ]
}
```

| Field                    | Type                            | Required | Notes                                                                    |
| ------------------------ | ------------------------------- | -------- | ------------------------------------------------------------------------ |
| `purchaseOrderId`        | `uuid`                          | Yes      | PO this return is raised against. Must be `CONFIRMED`, `PARTIAL`, or `RECEIVED` |
| `grnId`                  | `uuid`                          | No       | GRN this return traces back to (for traceability)                        |
| `returnDate`             | `ISO date string`               | No       | Defaults to current date                                                 |
| `reason`                 | `string`                        | Yes      | Overall reason for the return                                            |
| `remarks`                | `string`                        | No       |                                                                          |
| `items`                  | `CreatePurchaseReturnItemDto[]` | Yes      | Min 1 item                                                               |
| `items[].rawMaterialId`  | `uuid`                          | Yes      |                                                                          |
| `items[].batchId`        | `uuid`                          | Yes      | Qty deducted from this batch's `availableQuantity` at creation           |
| `items[].grnItemId`      | `uuid`                          | No       | For traceability to the specific GRN line                                |
| `items[].purchaseItemId` | `uuid`                          | No       | For traceability to the specific PO line                                 |
| `items[].quantity`       | `number`                        | Yes      | Min 0.01; must not exceed `batch.availableQuantity`                      |
| `items[].unitPrice`      | `number`                        | No       | **Ignored** — always taken from `batch.unitCost`                         |
| `items[].reason`         | `string`                        | No       | Per-item reason                                                          |

### 2. List Purchase Returns (Paginated)

```
GET /purchase-returns
Permission: purchases.read
```

#### Query Parameters

| Param             | Type                | Default     | Notes                                                                         |
| ----------------- | ------------------- | ----------- | ----------------------------------------------------------------------------- |
| `page`            | `number`            | `1`         | Min 1, Max 100                                                                |
| `limit`           | `number`            | `10`        | Min 1, Max 100                                                                |

| `purchaseOrderId` | `uuid`              | —           | Filter by PO                                                                  |
| `grnId`           | `uuid`              | —           | Filter by GRN                                                                 |

| `startDate`       | `ISO date string`   | —           | `returnDate >=`                                                               |
| `endDate`         | `ISO date string`   | —           | `returnDate <=`                                                               |
| `sortBy`          | `string`            | `createdAt` |                                                                               |
| `sortOrder`       | `"ASC"` \| `"DESC"` | `"DESC"`    |                                                                               |

#### Response `200 OK`

```json
{
  "data": [{ "...": "same shape as Create response" }],
  "meta": {
    "total": 14,
    "page": 1,
    "limit": 10,

  }
}
```

### 4. Update Purchase Return

```
PATCH /purchase-returns/:returnId
Permission: purchases.update
```

**Only `DRAFT` returns can be edited.** Performs a differential items update: items with an `id` are updated, items without an `id` are created (require `rawMaterialId`, `batchId`, `quantity`), and existing items omitted from the array are deleted.

**Stock side-effects on diff:**

| Item Change              | Stock Impact                                      |
| ------------------------ | ------------------------------------------------- |
| Item deleted             | Release reserved qty back to batch + raw material |
| Item qty/batch changed   | Release old reservation; reserve new batch/qty    |
| New item added           | Reserve qty from the new batch immediately        |

`unitPrice`/`totalPrice` for each item is always sourced from the batch's `unitCost` — client values are ignored.

#### Path Parameter

| Param      | Type   | Notes              |
| ---------- | ------ | ------------------ |
| `returnId` | `uuid` | Purchase Return ID |

#### Request Body

All fields optional.

```json
{
  "grnId": "grn-uuid",
  "returnDate": "2026-06-19",
  "reason": "Updated reason after inspection",
  "remarks": "Inspected by QC — batch fully rejected",
  "items": [
    {
      "id": "return-item-uuid",
      "quantity": 25
    },
    {
      "rawMaterialId": "rm-uuid-2",
      "batchId": "batch-uuid-2",
      "quantity": 10,
      "reason": "Additional defective items found"
    }
  ]
}
```

| Field        | Type                            | Required | Notes                                                                                              |
| ------------ | ------------------------------- | -------- | -------------------------------------------------------------------------------------------------- |
| `grnId`      | `uuid`                          | No       |                                                                                                    |
| `returnDate` | `ISO date string`               | No       |                                                                                                    |
| `reason`     | `string`                        | No       |                                                                                                    |
| `remarks`    | `string`                        | No       |                                                                                                    |
| `items`      | `UpdatePurchaseReturnItemDto[]` | No       | With `id` = update; without `id` = create (need `rawMaterialId`, `batchId`, `quantity`); omitted existing = deleted |

#### Response `200 OK`

Full updated purchase return (same shape as [Create response](#1-create-purchase-return)).

#### Errors

```json
{ "statusCode": 400, "message": "Only DRAFT returns can be edited" }
{ "statusCode": 400, "message": "New return items require rawMaterialId, batchId, and quantity" }
{ "statusCode": 400, "message": "Return quantity 150 exceeds available quantity 80 in batch RM-202606-0002" }
```

### 5. Update Return Status

```
PATCH /purchase-returns/:returnId/status
Permission: purchases.update
```

Transitions the return through its lifecycle. Valid transitions and their side effects:

| Target Status | Allowed From         | Requires               | Side Effects                                                                                                       |
| ------------- | -------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `PENDING`     | `DRAFT` (≥ 1 item)   | —                      | None — status only                                                                                                 |
| `APPROVED`    | `PENDING`            | —                      | Sets `approvedById`, `approvedAt`                                                                                  |
| `REJECTED`    | `PENDING`            | `reason` field         | Sets `rejectedById`, `rejectedReason`. **Releases all reserved batch quantities back to stock**                    |
| `COMPLETED`   | `APPROVED`           | —                      | Sets `completedAt`. Increments `batch.returnedQuantity` per item. Creates `RawMaterialBatchConsumption` audit log  |
| `CANCELLED`   | `DRAFT` or `PENDING` | —                      | **Releases all reserved batch quantities back to stock**                                                           |

> **`DRAFT` is not a valid target** — you cannot move a return back to `DRAFT` once it has been submitted.

#### Path Parameter

| Param      | Type   | Notes              |
| ---------- | ------ | ------------------ |
| `returnId` | `uuid` | Purchase Return ID |

#### Request Body

```json
{
  "status": "REJECTED",
  "reason": "Items were within acceptable tolerance limits"
}
```

| Field    | Type           | Required    | Notes                                                          |
| -------- | -------------- | ----------- | -------------------------------------------------------------- |
| `status` | `ReturnStatus` | Yes         | `PENDING`, `APPROVED`, `REJECTED`, `COMPLETED`, or `CANCELLED` |
| `reason` | `string`       | Conditional | **Required** when `status = REJECTED`; ignored otherwise       |

#### Response `200 OK`

Full updated purchase return (same shape as [Create response](#1-create-purchase-return)).

#### Errors

```json
{ "statusCode": 400, "message": "Only DRAFT returns can be submitted (moved to PENDING)" }
{ "statusCode": 400, "message": "Cannot submit a return with no items" }
{ "statusCode": 400, "message": "Only PENDING returns can be approved" }
{ "statusCode": 400, "message": "Only PENDING returns can be rejected" }
{ "statusCode": 400, "message": "A reason is required when rejecting a return" }
{ "statusCode": 400, "message": "Only APPROVED returns can be completed" }
{ "statusCode": 400, "message": "Only DRAFT or PENDING returns can be cancelled" }
{ "statusCode": 400, "message": "Invalid target status: DRAFT" }
```

### 6. Delete Purchase Return

```
DELETE /purchase-returns/:returnId
Permission: purchases.delete
```

Hard-deletes a return. **Only `DRAFT` returns can be deleted.** Before deletion, all reserved batch quantities are released back to stock.

#### Path Parameter

| Param      | Type   | Notes                        |
| ---------- | ------ | ---------------------------- |
| `returnId` | `uuid` | Purchase Return ID to delete |

#### Response `200 OK`

```json
{
  "message": "Purchase return deleted successfully"
}
```

#### Errors

```json
{ "statusCode": 400, "message": "Only DRAFT returns can be deleted" }
{ "statusCode": 404, "message": "Purchase return \"returnId\" not found", "error": "Not Found" }
```

## Frontend Implementation Notes

### Status Badge Colors (suggested)

| Status      | Color        |
| ----------- | ------------ |
| `DRAFT`     | Gray         |
| `PENDING`   | Amber/Orange |
| `APPROVED`  | Blue         |
| `REJECTED`  | Red          |
| `COMPLETED` | Green        |
| `CANCELLED` | Red/Muted    |

### Stock Warning Banner

Show a yellow info banner on the Create/Edit screens:

> "Creating or editing this return immediately reduces available stock from the selected batch — even while the return is still a draft. Cancelling or rejecting will restore the reserved stock."

### Typical Screen Flows

**Purchase Returns List Screen**
- `GET /purchase-returns` with `search`, `status`, `purchaseOrderId`, `supplierId`, date range, pagination.
- Status action buttons per row: show valid next actions based on current status (see [Update Return Status](#5-update-return-status) table).

**Create Return Screen**
1. Select a PO from `GET /purchase-orders/dropdown` (filter client-side to `CONFIRMED`/`PARTIAL`/`RECEIVED`).
2. Optionally select a GRN linked to that PO.
3. For each item: select `rawMaterialId`, then select `batchId` (fetch available batches from `GET /raw-material-batches?rawMaterialId=:id` — filter by `availableQuantity > 0`).
4. `POST /purchase-returns`.

**Return Detail Screen**
- `GET /purchase-returns/:returnId`.
- Show items table with `quantity`, `unitPrice`, `totalPrice` (readonly).
- Show approval list if `approvals[]` is non-empty.
- Action buttons based on `status`:
  - `DRAFT` → "Submit", "Edit", "Delete"
  - `PENDING` → "Approve", "Reject" (show reason input on reject), "Cancel"
  - `APPROVED` → "Complete"
  - `REJECTED` / `COMPLETED` / `CANCELLED` → Read-only

**Rejection Flow**
- Show a modal asking for a rejection reason (min 1 character).
- `PATCH /:returnId/status` with `{ status: "REJECTED", reason: "..." }`.
- After rejection, show a green toast: *"Return rejected — stock has been restored to the batch."*

**Batch Selection Helper**
When selecting a batch for a return item:
- Use `GET /raw-material-batches?rawMaterialId=:id` and filter client-side to `availableQuantity > 0`.
- Display: `{batchNumber} — {availableQuantity} {uom.symbol} available @ Rs. {unitCost}`.
- Disable batches with `availableQuantity === 0`.

### Decimal/Number Handling

`totalAmount`, item `unitPrice`, and `totalPrice` are returned as **JS numbers**. No conversion needed.
